# Demiurge — project notes for Claude

A No Man's Sky-style **procedural planet** prototype. Three.js **WebGPU** renderer. The vertical slice: seamless orbit→surface, terrain is a pure function of `(seed, position)`. Two camera modes: a globe/orbit camera and a first-person "walk" mode.

## Running & verifying
- **The user runs and verifies the app themselves.** Do NOT start the dev server, open a browser, use Playwright, or take screenshots to "check" rendering — write the code and hand it off. (WebGPU also won't render in a headless browser in this environment.)
- `npm run dev` = Vite dev server (the user runs it). `npx tsc --noEmit` = the typecheck gate (keep it green).

## World scale — single source of truth
`src/planet/worldConstants.ts` owns all scale constants. Do not hardcode these values elsewhere.

- `RADIUS = 500_000` (500 km), `HEIGHT_SCALE = 12_000` (12 km relief), `RADIUS_REF = 50_000`, `HEIGHT_SCALE_REF = 1_200`, `RES_REF = 256`
- The pipeline is angular/normalized; `RADIUS` and `HEIGHT_SCALE` enter **only** at final geometry (`r = RADIUS + hNorm * HEIGHT_SCALE`), camera maths, and absolute-physical quantities. fp32 holds at 500 km (origin-relative vertices; the 500k camera/chunk offset cancels in fp64 CPU-side modelView before the GPU).
- **Uniform-scale invariant:** this is a true 10× scale of the 50km/1200 baseline (relief ratio 2.4% preserved). When you add a parameter that depends on absolute height or distance, scale it as `param * (HEIGHT_SCALE / HEIGHT_SCALE_REF)` — otherwise it comes out 10× wrong. Example: `bUpliftRate` is authored at 40 m/step at the 1200 baseline, so Planet.ts initializes it as `40 * (heightScale / HEIGHT_SCALE_REF) = 400 m/step` at 500 km.
- `deriveSlopeThresh(baseThresh, radius, heightScale, res)` and `deriveErosionRes()` (returns 256, fixed, not scaled) live in `worldConstants.ts`.

## Terrain LOD
- Cube-sphere **quadtree** of heightfield chunks: `Planet.ts`, `QuadtreeNode.ts`, `ChunkMesher.ts`, `faceBases.ts`. Each chunk is a `resolution`×`resolution` grid (resolution = 32). Scale values come from `worldConstants.ts` (see above).
- **Screen-space-error selection** (`computeProjPx` / `selectLeaves`): a node splits when its projected size exceeds `resolution * targetTriPx` px. `targetTriPx` (default 2.0, range 0.5–8) and `maxDepth` (default 10, range 8–20) are live lil-gui sliders. Distance is nearest-point to a per-node bounding sphere whose center is the **terrain-height-adjusted `surfaceCenter`** — measuring to sea level under-refined elevated terrain (that was a bug; don't revert it).
- **Frustum culling** (`collect` vs `_localFrustum`): the build only refines/meshes chunks in the camera frustum (dilated ~1 chunk so turning doesn't pop). Off-screen stays coarse. This is a major perf win — keep it.

## Web Worker meshing — the key perf system
Chunk meshing runs on a **worker pool** OFF the main thread: `MeshWorkerPool.ts`, `meshWorker.ts`, `meshProtocol.ts` (N = `hardwareConcurrency-1`). The main thread no longer meshes — single-threaded meshing of the expensive ~14-octave tectonic heightFn was the bottleneck.

- **Determinism is critical.** Worker output must be **byte-identical** to the main thread or chunk seams crack. The terrain function is ONE shared factory — `terrainSampler.ts` `makeTerrainSampler` — used by both sides. Change terrain logic ONLY there; never fork it.
- The expensive tectonics/climate bake runs **once** on the main thread and is shipped to workers via `Tectonics.toBaked()/fromBaked()` and `Climate.toBaked()/fromBaked()` (workers reconstruct query-only instances, no re-bake). `fromBaked` uses `Object.create`, so it must explicitly init every hot-path scratch field (field initializers don't run).
- `ChunkMesher.computeChunkArrays` = worker-safe compute core (raw typed arrays, no THREE GPU objects); `arraysToGeometry` builds the `BufferGeometry` on the main thread.
- Build queue: `drainBuildQueue` submits to the pool; `onWorkerResult` caches results (with a generation counter to drop stale results across `regenerate()`); `selectLeaves` consumes the cache.
- **Do NOT pre-enqueue the whole descent tree.** `enqueueDeepPath` was removed — with fast workers it flooded the queue (~20k chunks) and thrashed the cache. Level-by-level descent + frustum culling is correct.

## Meshing gotchas
- **Normals:** interior vertex normals come from mesh geometry (neighbor-position cross products, cheap). **Border** vertices use **sphere-tangent central differences** — this is the cube-face SEAM FIX (face-local normals caused a lighting crease along the 12 cube edges). Don't change the border method.
- The heightFn (tectonic Voronoi query + ~14-octave FBM + ridged + climate + process palette) dominates per-chunk cost. Ridged-noise amplitude/octaves are tuned low to avoid jagged spikes at fine LOD.
- Skirts (sized proportional to chunk) hide LOD/seam cracks.

## Terrain diversity — substrate, process palette, deposition

### Substrate: rockHardness field
`tectonics.ts` bakes a per-texel `rockHardness` [0,1] field: a 4-term blend of crust age + volcanic-arc proximity + crust type + FBM (stream 19), with composition-scaled contrast (`contrastScale = 0.25 + 0.75 * composition`). Query: `hardnessAt(dir)` — C1 bilinear lookup. Shipped via `TectonicsBaked.rockHardness`.

**Differential erosion (active in B-path):** per-cell erodibility `K0` and talus angle are modulated by `hardness` in the erosion bake (`erodibilityB` / `talusScaleB`). Hard rock → higher talus, more resistant → ridges/mesas. Soft → lower resistance → smooth basins/badlands. Also modulates `detailAmp` in `heightFn` via `hardnessTerm = 1.0 + HARD_DETAIL_BOOST*0.7*(rockHardness - 0.5)`.

### Process palette (heightFn — `terrainSampler.ts`)
Continuous smoothstep-weighted blends; streams 40/41/42; gated on BASE temperature only (no sun term):
- **Fluvial** (baseline)
- **Glacial** (stream 40): `PROC_GLACIAL_STR=0.55`; elev band [0.10, 0.35], temp [-40, 5]°C, moisture [0.20, 0.60]
- **Aeolian** (stream 41): `PROC_AEOLIAN_STR=0.50`; windSpeed [0.30, 0.75], aridity [0.00, 0.70], dune freq 22.0; wind-aligned dunes
- **Karst** (stream 42): `PROC_KARST_STR=0.30`; moisture [0.55, 0.90], solubility window [0.20, 0.65] of rockHardness

### Deposition differentiation
Fan/floodplain/delta classifier (`depositEnv` Uint8, ENV_FLOODPLAIN/FAN/DELTA) with mass-conserved lateral fan spread lives in the **frozen-flow path** of `erosion.ts`. `ChunkMesher` applies tints post-biome: floodplain `#a89270`, fan `#c4aa7a`, delta `#9a9080`; cap-rock tint `#7e7060` when hardness > 0.65.

**Caveat — see Known gaps below.** The planet ships on the **B-path** (`bActive:true`; `Planet` always supplies `upliftForcing`), which leaves `depositEnv` all-zero. Fan/floodplain/delta color differentiation is therefore inactive in the rendered planet. Substrate hardness differential erosion IS active.

## Wind system (`climate.ts`)
`bakeWind()` produces a baked cube-map field (windX/Y/Z + windSpeed) consumed by `windAt(dir, out)` and `windSpeedAt(dir)`.

**Structure:** 3-cell zonal base (trades westward / westerlies eastward / polar easterlies westward, driven by `retrograde * -cos(2*bandCount*absLat)`) + Coriolis cross-isobar tilt (right N / left S, max at equator → geostrophic at poles) + streamfunction Gaussian pressure-vortex swirls (highs ~30°, lows ~60°, hemisphere-signed rotation, calm eye). Vortex placement is deterministic fixed-order from `deriveSeed(seed, 201)`. Stream 201.

**Equator taper (baked):** `equatorTaperWidth` param (radians, default 0.20, range 0–0.5) drives an equator mask `eqMask = smoothstep(0, sin(equatorTaperWidth), |dir.y|)` applied to the summed vortex swirl and its speed contribution only — zonal bands and Coriolis tilt are untouched. Effect: highs/lows are hemisphere-confined and a calm ITCZ/doldrums belt emerges at lat=0. Pure function of `dir.y`, no new RNG draws; stream-201 vortex placement is unchanged. Threaded `Planet._windEquatorTaper` → `terrainSampler` `SamplerOpts.equatorTaperWidth` → `Climate` ctor.

**Transient weather layer (visualization-only):** `windAtTime(dir, t, out)` returns the static climatological mean PLUS a transient delta: (i) the persisted vortex table re-evaluated with longitude-only drift and a sinusoidally pulsing amplitude (latitude preserved so equator confinement holds); (ii) a time-evolving divergence-free curl-noise eddy field — 2-octave streamfunction via `createNoise3D` on stream 202, finite-difference tangent gradient, `eddyVel = dir × gradΨ` — weighted by a `stormWeight` that is zero in the doldrums (shares `eqMask`) and fades at poles. Deterministic in `(dir, t)`; zero-alloc. **Determinism note:** terrain meshing and aeolian dunes read the static `windAt()` (millennia-mean) only; workers never call `windAtTime`; `toBaked/fromBaked/ClimateBaked` are unchanged — the transient layer cannot affect terrain or break worker determinism. `Planet.animateWind(t)` self-gates on `windDebug.visible`, so there is zero per-frame cost when the wind view is off.

Consumed by: static `windAt()` → aeolian dune alignment + terrain sampler + `WindFlow` streakline advection; `windAtTime()` → `WindDebug` animated arrows; static `windAt()` baked to equirectangular texture → `VolumetricClouds` advection/domain warp (see below).

**Arrow visualization:** `WindDebug.ts` (mirrors `TectonicsDebug` structure); uses shared `arrowGeometry.ts` (`buildArrowGeometry`). Arrow length = `radius * 0.045`; bearing-hue coloring; positions sampled via Fibonacci sphere at `surfaceRadius + heightScale * 2.0`. Re-samples `windAtTime` each frame when visible. Shows the instantaneous direction field — each arrow re-points and resizes in place but conveys no flow continuity.

**Flow visualization:** `WindFlow.ts` — an advected-particle streakline overlay (earth.nullschool.net "living wind map" look) that **coexists** with the arrow overlay. Both live in the `wind` view (hotkey 6) and are independently toggleable via GUI checkboxes. Particles (default 8000) are advected each frame along the **static mean `windAt(dir)`** via a great-circle step (`pNew = normalize(p·cos(arc) + w·sin(arc))`, `arc = flowSpeed·speed·dt`). **Uses `windAt`, not `windAtTime`** — ~10× cheaper (4 bilinear lookups vs the vortex loop + curl-noise finite differences), which funds the higher particle count; the streaks still curve through every band/vortex, only the slow in-place eddy *wobble* is dropped (invisible in moving streaks). `flowSpeed` defaults to **0.6** (range 0–3.0) and is an **angular rate** — it must be high enough that the head visibly *translates* and the trail spans a readable arc, else the streak degenerates to a point that just re-orients in place (looked like wiggling, not flowing — that was the bug; don't lower the default back to ~0.15). Each particle keeps a ring buffer of its last K positions (trail length, default 12), rendered as one batched `THREE.LineSegments`. **Visible-cap dynamic LOD:** every frame all particles are kept inside the camera-facing spherical cap (≈ visible hemisphere, cos cutoff = `radius/(radius+altitude)` with a small off-screen margin, half-angle clamped ≤ ~11° at the surface). A particle that advects past the cap edge, or hits its jittered lifetime, or drops below the calm threshold, is **teleported to a uniform-random direction inside the cap** (trail collapsed to a point so no streak is drawn across the sphere). So the whole fixed budget is always spent on what's on screen and density concentrates as you zoom in; the hidden hemisphere costs ~0. `Planet.animateWind(t, dt, camWorldPos)` passes the camera direction (planet-local, via the 1-frame-stale `_invWorldQuat`) + altitude in. Material: `LineBasicNodeMaterial` (from `three/webgpu`), additive blending, `depthWrite` off; colour is a **uniform cyan** × head→tail brightness × per-particle speed (faster = brighter), no per-vertex alpha — additive convergence brightens knots toward white (the reference look). Particles render on a constant shell at `radius + heightScale·2.0` — no per-frame terrain-height query. Uses a LOCAL mulberry32 PRNG (fixed seed) for scatter/respawn — NOT a reserved RNG stream; does not touch terrain, meshing, workers, or `climate.ts`. Self-gates on visibility (zero per-frame cost when the wind view is off); allocation-free hot path. **Known ceiling:** pure-CPU caps ~8–12k visible lines at 60fps; reference-tier orbit-wide density needs baked streamline geometry or GPU-advected particles (compute — risky here, crashed the device before). `ponytail:` per-particle cap test, no explicit tile tree — add cubemap-tile buckets only if culling proves insufficient.

GUI sliders (rebake): swirl strength, # highs, # lows, Coriolis strength, vortex size, lat spread, equator taper. Live (transient — calmed so the arrows don't jitter): storm drift (0–0.1, def 0.010), pulse rate (0–1.5, def 0.10), pulse depth (0–1, def 0.18), eddy strength (0–1, def 0.20), eddy scale (1–20, def 6), eddy time scale (0–1.5, def 0.12). Wind folder checkboxes: `wind arrows` (def on), `wind flow` (def on). Arrow live sliders: arrow density, arrow scale. Flow live sliders: flow density (1000–30000, def 8000), flow speed (0–3.0, def 0.6 — angular advection rate), trail length (2–24, def 12), particle life (1–10 s, def 4).

## Volumetric clouds (`VolumetricClouds.ts`)
A **full volumetric raymarched** cloud layer (it REPLACED the old flat `CloudShell` but keeps the same external API — field `cloudShell`, `get visible`, `setVisible`, `rebuild`, `dispose`, all `setCloud*` setters — so `Planet.ts` compiles unchanged; `main.ts`/`Planet` references still read `cloudShell`). Renders **only in the normal view**, hidden elsewhere so it doesn't occlude data overlays (centralized in `main.ts` `applyView` → `planet.setCloudShellVisible(ui.view === 'normal')`). Motivation: the arrow/streakline overlays convey wind direction and motion but not the massed gestalt of weather; the cloud layer gives broad, lit cloud formations that follow the wind.

**Geometry and march:** a `DoubleSide` `SphereGeometry` shell at the annulus outer radius; the `MeshBasicNodeMaterial` fragment **ray-marches a lit 3D cloud medium across the spherical annulus** `innerR..outerR` (= `radius + heightScale * cloudBase` .. `+ heightScale * (cloudBase+cloudThick)`, capped 2.45× to stay below the atmosphere shell) in WORLD frame. Full 3-case ray/2-sphere intersect handles camera outside / between layers / inside inner. `NormalBlending`, `depthWrite` off, `renderOrder` 10, `frustumCulled` false. Density is sampled in **planet-local frame** via a per-frame `_uInvRot` mat3 (so clouds ride the planet's spin/tilt and match the equirect bakes).

**Density shape:** **Perlin-Worley** — a 2-octave inverted-**Worley** cellular FBM (`mx_worley_noise_float`, jitter 1, metric 0 euclidean; `1−F1` so cell centres are lumps → real cauliflower structure) blended with `mx_fractal_noise_float` Perlin FBM by `uBillow` (= Worley weight). This replaced the old sum-of-`|mx_noise_float|` billow, which read as uniform popcorn. **Worley is expensive** (27-cell loop per sample, run at every march + light-march step) so it's capped at 2 octaves (half-res offscreen pass affords the headroom instead). NB: `mx_worley_noise_float` is under-typed in three's `.d.ts` (caps args at 2) but its runtime overload dispatches by exact arg count and needs `(p, jitter, metric)` — call via the cast `worley` wrapper. Detail erosion is **Nubis remap-from-edge** (`baseShape.remapClamp(erodeAmt, 1)`), NOT a flat subtract: it dilates dense cores and carves only the low-density fringe. The erosion modifier is height-graded (`mix(hiFBM, 1-hiFBM, saturate(heightFrac*5))`) → round billowy bottoms, torn wispy tops. A vertical `profile` (smoothstep `roundBase` rise × inverse `billowTop` erosion) shapes the slab. **Motion = great-circle advection of the sampling DIRECTION** along the local wind: `dAdv = normalize(dLocal·cos(arc) + windDir·sin(arc))`, `arc = scrollSpeed·speed·time`, `windDir = windVec/max(|windVec|,1e-4)` (guards `normalize(0)` at calm eyes/doldrums; there speed→0 so arc→0 and dAdv=dLocal). The whole field **flows coherently over the sphere** — masses drift and visibly *merge* — and being a bounded rotation it never collapses over long sessions (the earlier linear noise-space `drift` morphed in place and blinked clouds in/out against the static gate). Noise is sampled at **`dAdv·(uScale + heightFrac·VERT_NOISE)`** — the sample RADIUS grows with altitude through the annulus, so the noise varies across the shell THICKNESS as a true 3D volume (clouds have top-to-bottom structure). Sampling at a constant radius (just `dAdv·scale`) extruded a 2D direction map into flat-topped/flat-bottomed **slabs** — the original "blocky/cartoon" look. (+ a small wind-aligned domain warp.) **Coverage/favorability stays sampled at the static `dLocal`** so clouds cluster in climate-fixed humid zones and thin as they drift into dry air (natural formation/dissipation). `scrollSpeed` is an **angular** rate (rad/s).

**Lighting (lit medium):** **dual-lobe Henyey-Greenstein** (forward lobe = `uHgAnisotropy` for the silver lining toward the sun + a fixed weak back lobe `g=-0.3` so anti-sun faces stay gently lit, not black). Per-sample **light-march** toward `_uSunDir` (`uLightSteps` taps) accumulates optical depth. Sun lighting uses **multi-octave "multiscatter" Beer** (Wrenninge/Hillaire): the single-scatter term is summed over 3 octaves with `aⁿ/bⁿ/cⁿ` (=`0.5ⁿ`) scaling — each dimmer, penetrating deeper (softer extinction), more isotropic — so thick interiors **glow softly** instead of crushing flat (the voluminous look), while thin edges stay dark via the **view-gated Beer-powder** term (`saturate(-0.5·cosθ+0.5)`, anti-sun hemisphere only; `uPowder` strength). Cool blue-grey ambient (`uAmbient`, def **0.08** — low for shading contrast; now altitude-graded: bluer sky tint above, darker ground tint below, mixed by sample heightFrac) + warm sun color. **Forward phase lobe is Cornette-Shanks** (energy-conserving; sharper, more physical silver lining than plain HG) — the weak back lobe stays HG `g=-0.3`. **Cloud texture** — (a) sample brightness is tied to local density (`texVar = mix(0.5, 1, saturate(d·2.2))`) so the Worley structure shows in colour (thin = greyer, dense = white); (b) a **fine density mottle** in `densityCore` (`mx_noise_float(pAdv·10)`, multiplies density by `mix(0.45,1,mottle)`, sampled at the advected `pAdv` so it drifts with the cloud) → density/opacity cycles white↔grey↔translucent-holes instead of flat opaque white; (c) **specks**: the coverage threshold is capped (`t0 = min(t0raw, 0.93)`) so the highest shape peaks poke through even in the clearest regions → small scattered fair-weather clouds dotting clear sky. All in `densityCore` → cache-safe and drift correctly. View-ray Beer extinction accumulates transmittance; early-out when `transmittance < 0.01`.

**Loading overlay** (`index.html` `#loading` + `main.ts`): a CSS-spinner + progress-bar overlay shown in markup (so boot is never a black screen — the spinner is compositor-animated so it spins through the synchronous planet bake). `main.ts` `setProgress()` updates it at milestones (renderer init 25% → after `new Planet` 75% → first frames 100%) with `await nextFrame()` yields so it repaints; fades out at `frameCount > 4` (shaders compiled, planet on screen).

**Performance / sampling:** **empty-space skipping is the main perf lever** and must stay — a full march of every step overloads the GPU and *hangs the page* (regression seen when it was removed + step count raised). The march scouts empty air with `bigStep` (2× fine); on the FIRST hit it backs up one big step (clamped to `tEnter`) and switches to fine marching via a `refined` toVar (back-up so the near face isn't quantized to the coarse scout grid → blocky). Fine (in-cloud) step is `min(pathLen/uStepCount, (outerR−innerR)·0.11)` — **capped to ~11% of the annulus THICKNESS** so horizon-grazing rays (very long near-tangent path) stay finely sampled instead of divided into coarse chunks (that coarse sampling, dithered, was a heavy **grain** — the cap is the main grazing-grain lever; lower = finer/less grain but shorter reach). Grazing rays may not reach `tExit` in budget but the early-out (`transmittance < 0.01`) covers dense cases and far clip is graceful. The `uLightSteps` light-march fires only inside cloud. **Distance LOD** (CPU-side in `update()`, uses `|camWorldPos|−radius` = altitude): up close (alt < ~2·heightScale) full `_baseStepCount` (48, the "step count" slider = close-up MAX) + fine cap `uStepCap=0.11`; from orbit (alt > ~0.4·radius) drops to `_minSteps` (8) + coarse cap (~1.0, so few steps still span long grazing paths) — raymarching is the cost and volumetric depth isn't perceptible from far (NMS does the same: cheap from orbit, volumetric up close). Smoothstep blend, no popping. `uStepCount`/`uStepCap` are set per frame. **Blue-noise ray-start dither** via `interleavedGradientNoise(screenCoordinate.xy)` at **0.3 amplitude** — screen-locked/static, no TAA, so a faint stable grain remains; the proper fix is temporal accumulation (an offscreen history + reproject pass — NOT yet implemented), with the **half-res offscreen pass** (`CloudCompositor`, opt-in) as the cheap interim softener (see below).

**Half-res offscreen pass (perf / grain, opt-in — `CloudCompositor.ts`):** the cloud march is the cost. `CloudCompositor` renders the cloud shell to a **half-res `RenderTarget`** in its own pass (cloud isolated onto a transient render LAYER during the pass, restored to 0 after — so the default path is untouched), then composites it over the main scene with a premultiplied `QuadMesh`. Quartering cloud pixels ≈ doubles perf, and the bilinear upsample softens the residual grain. `densityCore(dLocal, pLen)` (local dir + radius) is the worker-safe density core. Gated behind the `half-res (offscreen, exp.)` GUI toggle (default off); `main.ts` branches `cloudCompositor.render(...)` vs `renderer.render(...)`. **Foundation for temporal accumulation** (history + reproject — NOT yet implemented; that's the real grain kill). NB a compute-baked 3D `Storage3DTexture` density cache was tried and **removed** — it read blocky, could crash the WebGPU device, and half-res supersedes it.

**Depth occlusion:** the renderer uses `logarithmicDepthBuffer:true`; `viewportLinearDepth` decodes via the perspective inverse and the two don't compose, so the depth clamp is **skipped** — clouds-always-in-front. Correct because `cloudBase ≥ 1.2·heightScale` (~14.4 km) sits above peak terrain relief (~12 km), so from orbit and from the surface looking up the clouds are above terrain/camera.

**Wind texture:** a 512×256 equirectangular RGBA8 `DataTexture` baked once (and on `rebuild()`) from `climate.windAt(dir)` — the static climatological mean. Packs tangent wind direction in RGB (UN-normalized, recovered as `xyz*2-1`), speed in A. Sampled via `dir → (lon, lat)` UV matching the bake convention.

**Coverage = domain-warped weather map (the "random → continuous" fix):** the key structural lesson (from the Nubis/iq research, 2026-06-18) — cloud PLACEMENT must come from a **low-frequency, domain-warped weather map**, NOT from the high-frequency shape noise (which gives random scattered patches). The shape only carves silhouette detail INSIDE covered zones. The weather map: `warpVec = vec3(3× mx_noise_float(dLocal·1.8))·0.35 + windDir·speed·0.4` (iq domain-warp folds it + the curl-like vortex wind drags it into spirals/fronts); `dWeather = normalize(dLocal + warpVec)`; `weatherShaped = smoothstep(0.42,0.58, fbm(dWeather·1.8, 4oct))` → big cloudy/clear regions. This is the DOMINANT term in `t0` (`uWeatherWeight` "weather systems" slider, def **0.45**). NB: NMS clouds are NOT actually Earth-organized (2D scrolling texture from orbit) — Earth is a harder benchmark; the transferable trick is domain warping.

The coverage threshold `t0` (lower = more cloud) is then `uCoverage − weatherWeight·(weatherShaped−0.5)·2 − itczWeight·latSigned − favWeight·(fav−0.5)`, three drivers:
1. **Latitude circulation bands** (`uItczWeight`, "latitude bands" slider, def **0.13** — carves the reliable clear subtropical desert belt at ~30°; convergence swirls keep it organic, not rigid rings). `|dLocal.y| = |sin(lat)|`; `itcz = 1−smoothstep(0,0.22,|y|)` (cloudy equator), `storm = smoothstep(0.55,0.74,|y|) − smoothstep(0.86,0.96,|y|)` (cloudy ~45-60° storm tracks); `latSigned = (max(itcz,storm) − 0.5)·2 ∈ [−1,+1]` → +1 in the cloud bands, −1 in the **clear subtropical highs (~30°, descending/drying air → the desert belt; this is what keeps the Sahara/Atacama cloud-free)** and clear poles.
2. **Regional moisture + convergence** (`uFavWeight` def **0.58**, `convWt` def **0.8** — high so the wind's convergence/fronts/cyclones DOMINATE placement → clouds form continuous coherent **systems** like Earth, not random noise. Coverage threshold also raised to 0.65 so big CLEAR regions (deserts/subtropical oceans) emerge.) — `fav = saturate(moistWt·moisture + convWt·convergence)` from the baked fav texture (G=moisture, B=tanh convergence). Humid/converging(low-pressure) → cloud; dry/diverging(sinking high) → clear. This is the swirl driver; it also carves continental deserts. Pairs with **wind warp** (`uWarp` def **0.4**, was 0) which shears cloud shapes along the wind flow so they follow the cyclonic spirals.
3. **Weather variety** (`uWeatherWeight`, "weather variety" slider, def **0.15** — kept weak so it doesn't wash the bands into random scatter) — low-freq `mx_fractal_noise_float(dAdv·2.5)` drifting with the wind.

`t0 = coverage − itczWeight·latSigned − favWeight·(fav−0.5) − weatherWeight·(weather−0.5)`. NB: an earlier version made the weather noise dominant (weight 0.4, bands off) → looked random; reverted to climate-bands-dominant.

**Determinism/scope:** **visualization-only** — the raymarch is a render-pass material that does NOT touch terrain, the mesh workers, or `toBaked/fromBaked`; it reads only the static climatological wind mean (consistent with the "wind is a static mean for terrain" decision). So none of the cloud shape/lighting/perf changes can break worker determinism. `climate.ts` is read-only. `Planet.animateWind(t, dt)` advances the cloud time + `_uInvRot`; the layer self-gates on `setCloudShellVisible` (zero per-frame cost when hidden).

## Atmosphere shell (`Atmosphere.ts`)
A tunable atmospheric scattering shell — always-on appearance in both orbit and walk mode (not a view mode). From orbit it shows a blue glow at the planet limb; from the surface it gives a blue sky (in-scattering). Black space falls out naturally because zenith/deep-space rays accumulate near-zero scatter.

**Geometry and material:** a `BackSide` `SphereGeometry` at `radius + heightScale * atmHeightMul` (default mul ~2.5). `MeshBasicNodeMaterial`, `AdditiveBlending`, `depthWrite` off, `renderOrder` 5 — behind the cloud shell's `renderOrder` 10.

**TSL node graph (world frame):** computed entirely in world space using the built-in `cameraPosition` node + `positionWorld` + the shared `_uSunDir` uniform (same reference Planet uses for lighting — no per-frame camera upload needed; the planet sits at the world origin and is only spun, never translated). Terms: grazing/horizon thickening via `horizonGlow = pow(grazing, scaleHeight)` (guarded against zero so the slider min can't break it); a **zenith in-scatter floor** `density = skyFloor + (1-skyFloor)*horizonGlow` that lifts the whole sunlit dome (maps grazing 0→skyFloor, 1→1) so the sky reads blue overhead from the surface instead of going black — `skyFloor=0` reproduces the old limb-only behaviour exactly (space stays black); Rayleigh phase brightening toward the sun; a day/night fade (`sunUp`) so the night limb goes black (multiplies the floor too, so night stays dark); and a **per-channel Rayleigh reddening** factor `redden = exp(-betaR·density·k·slant)` (betaR ∝ 1/λ⁴, `slant` = view + sun slant air mass) that removes blue first along long slant paths → the terminator limb and the sky toward a low sun shift blue→orange→red (sunrise/sunset, horizon reddening). At high sun/overhead `slant≈0` → `redden≈(1,1,1)` so the tuned blue `tint` is preserved exactly. The constant `skyFloor` lift doubles as the cheap isotropic **multiple-scattering ambient** (Hillaire 1/(1-f) idea). NB **still additive/single-scatter** — no view-ray optical-depth integration, no Beer-Lambert background transmittance, no Mie, no aerial perspective on terrain (those remain open; aerial perspective is blocked on the log-depth→linear decode).

**Ownership:** built in `Planet` constructor, rebuilt on `regenerate()`, disposed in `dispose()`. Reuses `Planet._uSunDir` by reference. Visualization-only — no terrain, worker, climate, or RNG impact; consumes no RNG stream.

## Design principles
- **Everything is a slider** — no dropdowns, no selectable type lists. All parameters are continuous. Planet type emerges from physical dials (e.g. `composition` drives hardness contrast; `axialTilt` drives climate bands).
- **One physical dial per spectrum** — prefer a single param spanning Earth↔Venus↔Mercury rather than mode enums. This keeps the space smooth and avoids Earth-overfit.
- **Determinism contract** — one shared `makeTerrainSampler` factory, main + workers byte-identical. Bake-and-ship via `toBaked/fromBaked` (Object.create caveat: explicit scratch-field init required). C1 smoothstep sampling on all baked grids. Continuous blends not hard thresholds on baked fields.

## Decisions (settled — don't re-propose)
- **CDLOD vertex morphing:** tried, then reverted — ~doubled mesher cost for little gain; discrete LOD + skirts is used.
- **Full Nanite:** rejected — wrong tool for regenerable procedural heightfield terrain; WebGPU also lacks 64-bit atomics + multi-draw-indirect.
- **Simplex-noise-base terrain:** tried 2026-06-16, reverted same day — relief stays tectonic-simulation-driven.
- **Lake water-table landforms in heightFn:** tried (heightFn lake-flatten + marsh), reverted — produced a coarse 256²-grid staircase on small lakes. Lakes exist (smooth, blue) via bake-time erosion lake flatten only.
- **EROSION_RES:** fixed at 256, not scaled with RADIUS (`deriveErosionRes()` = 256). Scaling to 512+ caused main-thread freeze before first render.
- **B-path MinHeap / mfdNeighbors allocations:** hoisted out of the per-step loop (byte-identical output).
- **Wind field is intentionally a static climatological mean for terrain:** `windAt()` / the baked arrays are the millennia-average used by aeolian dunes and `terrainSampler`. The transient animated layer (`windAtTime`) is visualization-only — it never touches terrain, workers, or baked state.
- **Rivers: removed entirely (2026-08-13, commit "Remove rivers entirely").** Built over 2026-06-19 as four layers, deleted as four layers. **Root cause: the erosion bake is 256² ≈ 3 km/texel at RADIUS=500 km, and a river is ~100 m wide.** Every representation was therefore fighting the grid — an `accAt` vertex tint painted kilometres-wide blue smears, a riparian corridor haloed them wider, the `vIncision` carve could only cut a 6–9 km trough (pushed to 960 m deep chasing visibility → a 1:8 chasm), and `RiverNetwork.ts`'s traced water ribbons registered with none of it. **Don't re-propose rivers until `deriveErosionRes()` can afford ≥1024 (see EROSION_RES above — 512 already froze the main thread), or until drainage is traced analytically at query time instead of sampled off the bake grid.** More paint or a fifth layer will not fix a resolution problem. Full history preserved: checkpoint `4e645dd` (all four layers, working), cut-down `b4d6cca`.

## Known gaps / caveats
- **Deposition classifier (fan/floodplain/delta)** lives in the frozen-flow path. The planet always ships on the B-path → `depositEnv` all-zero → fan/floodplain/delta color tints inactive. Open follow-up to route classifier output into the B-path or merge paths.
- **Erosion `bUpliftRate` fallback:** `erosion.ts` has an internal fallback of `60 * (HEIGHT_SCALE / HEIGHT_SCALE_REF)` if `opts.bUpliftRate` is missing. `Planet.ts` always supplies it as `40 * (heightScale / HEIGHT_SCALE_REF)`, so the fallback is not hit in normal use — but don't silently drop `opts.bUpliftRate`.
- **HUD `KEYMAP_HELP`** in `Hud.ts` is stale — references only hotkeys 1–4, f, g; missing 5 (climate), 6 (wind), 7 (materials), 8 (wetness), c (cave). Update it when touching `Hud.ts`.
